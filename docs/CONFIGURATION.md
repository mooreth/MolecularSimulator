# Configuration reference

All application settings are in `IMD_client/config.toml`. The loader resolves the three configured file paths relative to the TOML file's directory.

## Files

```toml
[files]
data_file = "../c60_240_collide.data"
group_file = "../samson_groups.in"
simulation_file = "../simulation.in"
```

- `data_file`: LAMMPS data file loaded by `main.py` and rewritten by the SAMSON exporter.
- `group_file`: LAMMPS group commands generated by `SAMSON_groups_setup.py`.
- `simulation_file`: LAMMPS input containing force-field, timestep, integration, thermostat, and diagnostic commands.

## Network

```toml
[network]
imd_host = "127.0.0.1"
samson_host = "192.168.68.63" # Example: Windows workstation LAN address
imd_port = 5678
samson_port = 5679
```

The host settings are intentionally separate:

- `imd_host`: address the controller uses to connect to the LAMMPS IMD listener. Use `127.0.0.1` when LAMMPS and the controller run on the same machine.
- `samson_host`: address the controller uses to connect to the SAMSON receiver. On a remote Linux compute node, use the Windows workstation's LAN IP.

On the Windows SAMSON workstation, the receiver binds to all interfaces with `samson_host = "0.0.0.0"`. On the Linux controller, `samson_host` must be the actual reachable Windows IP; `0.0.0.0` is a bind address, not a destination address. Use separate machine-specific configuration files.

## Simulation and IMD cadence

```toml
[simulation]
steps_per_update = 10

[imd]
transfer_rate = 10
```

`steps_per_update` is the number of MD steps advanced in each controller cycle. `transfer_rate` is the interval, in MD steps, at which LAMMPS sends an IMD frame. Neither setting is the physical integration timestep; that remains in the selected LAMMPS input file.

## LAMMPS atom style

```toml
[lammps]
atom_style = "molecular"
```

The current reader/exporter supports `atomic`, `molecular`, `charge`, and `full` atom-record layouts. The chosen style must agree with the data file. This does not mean that the exporter preserves all topology associated with those styles: the current exporter writes only `Masses` and `Atoms`.

## Controls

```toml
[controls]
quit_key = "q"
```

## Linear motors

```toml
[motors.motor1]
group = "motor1"
fix_id = "motor1_move"
motion = "linear"
velocity = 10.0
axis = [1.0, 0.0, 0.0]
forward_key = "j"
stop_key = "k"
reverse_key = "l"
```

- `group`: LAMMPS group name created by the SAMSON exporter.
- `fix_id`: unique LAMMPS fix identifier for this motor.
- `motion`: `linear` or `rotate`.
- `velocity`: linear speed magnitude in the active LAMMPS distance/time units.
- `axis`: global XYZ direction. It is normalized by the configuration loader; reverse motion negates it.
- `forward_key`, `stop_key`, `reverse_key`: keyboard bindings.

Every configured motor group must exist in the generated group file before `main.py` starts. Do not assign the same atoms to multiple motors that can be commanded independently.

## Rotational motors

```toml
[motors.motor3]
group = "motor3"
fix_id = "motor3_rotate"
motion = "rotate"
axis = [0.0, 0.0, 1.0]
period = 10.0
pivot = "group_centroid"
forward_key = "u"
stop_key = "i"
reverse_key = "o"
```

`period` is one complete revolution in LAMMPS time units. `pivot` is either `group_centroid` or an explicit three-number XYZ position in Å. The centroid is calculated from the initial coordinates and atom IDs in the exported group file. Rotation is prescribed by LAMMPS `fix move rotate`; it is not force- or torque-driven.

## SAMSON display

```toml
[samson]
display_interval_ms = 16
```

Controls the SAMSON-side display update interval in milliseconds.

## Element overrides

```toml
[elements.overrides]
"1" = "C"
"2" = "H"
```

Optional explicit element labels keyed by LAMMPS atom type. When omitted, the application infers elements from masses for common elements. This is a visualization mapping, not a force-field atom-typing system.

## Export box padding

```toml
[export]
box_padding = 10.0
```

Adds this many Å around the current minimum and maximum SAMSON coordinates when the exporter rebuilds the simulation box.
